ШАБУР.EXE — ОТВЕТЫ ПРЕПОДАВАТЕЛЮ

Проверка сервера: GET /api/health -> 200, status online.
1. GET /api/orders -> 200. Заказ 102, Даня, quantity 999; заказ 105, Аня, quantity 0.
2. GET /api/orders/999 -> 404, detail «Заказ не найден. Проверь номер!»; GET /api/orders/104 -> 200, status «lost». 404 — статус HTTP, lost — поле JSON существующего заказа.
3. GET /api/users -> 200; id 2, «Картофельный повелитель», favorite «Пепперони». GET /api/users/2 -> 200. GET /api/users/50 -> 404.
4. POST /api/orders, Body/raw/JSON: {"participant":"Маша","pizza":"Маргарита","quantity":2} -> 201, status accepted, order_id TRAINING-2026. При quantity 0 или 999 -> 422. Учебные POST-запросы не сохраняются в общей базе.
5. GET /api/secret?code=shabur404 -> 200, badge «ОХОТНИК ЗА БАГАМИ»; неверный код -> 403.

План 45–50 минут: 10–12 мин введение и демонстрация GET/POST; 35 мин самостоятельная работа (6+6+7+8+8); 3 мин финал при 50-минутном занятии.

ВАЖНО: перед мероприятием проверить из сети колледжа /, /api/health, GET /api/orders и POST /api/orders. Cloudflare может быть недоступен у некоторых провайдеров в России. При проблемах заранее разместить тот же статический сайт и API на доступном хостинге или подготовить локальный резерв.
